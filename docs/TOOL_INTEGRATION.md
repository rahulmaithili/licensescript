# LicenseWala — Tool Developer Handoff
## How the desktop tool must activate with the website login

**Give this one file to whoever builds your tool.** It contains everything needed for the tool to open with the customer's LicenseWala website account (Google login), check their license/trial, auto-expire, and prompt renewal. No other document is required.

---

## 1. How it works (30-second version)

1. The tool shows a **"Login with Google"** button.
2. The customer signs in with the **same Google account** they used on https://licensescript.netlify.app — the password goes only to Google, never to the tool and never to our server.
3. Google gives the tool an **ID token**. The tool sends that token + the machine's hardware ID to our API.
4. Our server verifies the token with Google, finds the customer's license, and answers **active / trial / expired / no license**.
5. The tool opens only if the answer is active. It must re-check on **every start** (and ideally every few hours while running) — never trust a locally saved "days left".

## 3. Activation API — Path A (recommended): Google login

```http
POST https://licensescript.netlify.app/api/google-verify
Content-Type: application/json

{ "id_token": "<google id token>", "hwid": "<machine fingerprint>", "product_slug": "cdcms-pro" }
```

- `hwid` — a stable machine fingerprint generated by the tool (e.g. hash of motherboard/disk/CPU IDs). Must be identical on every run of the same machine.
- `product_slug` — optional. One of: `cdcms-pro`, `cdc-tools`, `all-in-one-master`. Omit it to accept a license for any product. Trial licenses are suite-wide and match any product.

**Response — license active:**
```json
{
  "active": true, "status": "active", "type": "paid",
  "email": "customer@gmail.com", "customer_name": "Ramesh Kumar",
  "product_name": "CDCMS Multi-Tool Suite (PRO)", "plan_name": "3 Months Pro",
  "license_key": "LW-XXXX-XXXX-XXXX", "expiry_date": "2027-01-15",
  "days_left": 87, "max_devices": 1,
  "message": "License activated via Google sign-in."
}
```
- Trial: `"type": "trial"` plus `"trial": true, "trial_ends_at": "<date>"`.
- Paid license inside its **3-day grace** after expiry: `"active": true, "status": "grace"` — keep the tool open, show the renew reminder from `message`.

**Response — not active** (always show `message` to the user and offer a button that opens `renew_url`):
```json
{ "active": false, "reason": "expired",        "expiry_date": "2026-10-01", "renew_url": "https://licensescript.netlify.app/pricing" }
{ "active": false, "reason": "trial_expired",  "expiry_date": "2026-10-12", "renew_url": "https://licensescript.netlify.app/pricing" }
{ "active": false, "reason": "no_license",     "renew_url": "https://licensescript.netlify.app/pricing" }
{ "active": false, "reason": "no_account",     "renew_url": "https://licensescript.netlify.app/pricing" }
{ "active": false, "reason": "device_mismatch","portal_url": "https://licensescript.netlify.app/account" }
```
Other `reason` values: `locked` / `paused` / `revoked` (tell the user to contact support), `invalid_token` / `email_unverified` (HTTP 401 — ask the user to sign in again), `rate_limited` (HTTP 429 — wait and retry; limit is 60 requests/minute per IP).

**HWID rules:** the first machine to check in is bound automatically; the same machine always passes; a different machine is rejected once the license's device slots (`max_devices`, default 1) are full. The customer can free slots from the website's `/account` page ("Reset devices").

## 4. Activation API — Path B: license key (backup method)

```http
POST https://licensescript.netlify.app/api/verify-license
Content-Type: application/json

{ "key": "LW-XXXX-XXXX-XXXX", "hwid": "<machine fingerprint>", "deviceName": "Desktop Tool" }
```
→ `{ "valid": true, "status": "active", "days_left": 87, "expires_at": "...", "product_name": "...", "plan_name": "..." }`
Trial keys (`LW-TRIAL-…`) work here too and add `"trial": true, "trial_ends_at": "..."`. Expired beyond grace → `"valid": false, "status": "expired"` with a `renewal_url`.

---

## 5. Free trial behaviour (automatic — nothing to build)

- Every customer who registers/signs in on the website automatically gets **one 7-day free trial** (per account, once ever). The trial appears in their website account with a "Free Trial" badge.
- The trial binds to the machine HWID on its **first** verification through either API path.
- Trials have **no grace period**: at expiry the API returns `trial_expired` and the tool must stop and prompt the user to buy a plan via `renew_url`.

---

## 6. Renew behaviour (tool must follow)

- On `expired` / `trial_expired`: stop premium features, show the message, open `renew_url` (https://licensescript.netlify.app/pricing) when the user clicks **Renew**.
- **No re-install, no new key entry:** once the customer renews on the website under the same Google account, the next `google-verify` call returns `active: true` again. For Path B, a renewed license keeps the same key.

---

## 7. Rules for the tool developer (important)

- **Never** ask for or store the customer's Google password — sign-in happens only on Google's own page/flow.
- ID tokens expire in ~1 hour. Keep the user signed in with Google's SDK and fetch a **fresh ID token** for every verification call.
- If the server is unreachable, you may allow a short offline grace (max 24 hours from the last successful check) — after that, block with a "connect to internet" message. Never extend the license expiry locally.
- Do not hard-code any API key or secret in the tool. The two endpoints above need no key — security comes from the Google token itself.
